# 第 1 話: 金床を据える

> 鋳造所の朝は、金床を据えるところから始まります。金床は、熱した鉄をのせてたたく、鉄の台です。これがなければ、何も作れません。
>
> Ethereum の鋳造所では、金床は **anvil** です。自分のパソコンの中だけで動く、自分だけのチェーンです。

**この話ですること**: チェーンを自分で立てる。利用者として使ってみる。そのあと、持ち主にしかできないことを試す。

**使う道具**: anvil（金床）、cast（鋳造する。決まった型のコマンドで、チェーンを読む・取引を送る）

[準備](00_setup.md) を済ませてから始めます。

## 1-0. 金床を据える

**タブ 1** で、anvil を動かします。このタブは、最後まで動かしたままにします。

```bash
anvil --port 8546 --order fees
```

- `--port 8546`: anvil の既定のポートは 8545 です。ほかの anvil とぶつからないように、1 つずらしています。
- `--order fees`: 「ブロックの中の順番を、手数料の高い順にする」という指定です。これは anvil の既定の値ですが、第 3 話の主役なので、はっきり書いています。

口座 10 個（それぞれ 10,000 ETH）と、秘密鍵と、最後に `Listening on 127.0.0.1:8546` が出ます。これで、金床が据わりました。

**タブ 2** に移って、手もとの道具を用意します。

```bash
cd eth-local-chain-primer
```

```bash
source helpers.sh
```

`helpers.sh` は、つなぎ先（`ETH_RPC_URL`）を、いま据えた金床（8546）に決めます。

口座を 2 つ、変数に入れます。この 2 人が、今日の登場人物です。

```bash
A=0xf39fd6e51aad88f6f4ce6ab8827279cfffb92266
```

```bash
B=0x70997970c51812dc3a010c7d01b50e0d17dc79c8
```

これは anvil の 1 つめと 2 つめの口座です。`cast rpc eth_accounts` で確かめられます。

タブ 2 を閉じて開き直したときは、`source helpers.sh` と、この 2 行をもう一度打ってください。

## 1-1. 据えたばかりの金床を見る

```bash
cast chain-id
```

```bash
cast block-number
```

```bash
cast balance $A --ether
```

出るはずの結果: `31337`、`0`、`10000.000000000000000000`。

- チェーン ID 31337 は、anvil の既定の値です。
- ブロック番号 0 は、まだ何も起きていないということです。金床の上は、まっさらです。
- `cast` は、本物のチェーンに使うのと同じコマンドです。窓口（JSON-RPC）の形が同じなので、道具は相手が anvil かどうかを区別しません。

## 1-2. まず、利用者として使ってみる

A から B に、1 ETH を送ります。

```bash
cast send --unlocked --from $A $B --value 1ether
```

```bash
cast block-number
```

```bash
cast balance $B --ether
```

出るはずの結果: `cast send` の出力の中に `blockNumber 1` と `status 1 (success)`。そのあと `1`、`10001.000000000000000000`。

- 取引を 1 本送ったら、ブロックが 1 つできました。anvil は、既定では「取引が 1 本来たら、すぐ 1 ブロック作る」動きをします（automine）。
- 本物のチェーンでは、ブロックは決まった間隔でできます。ここでは自分の金床なので、作り方を自分で選べます。第 3 話で、この automine を切ります。

ここまでは、本物のチェーンでもできることです。

## 1-3. 金床の持ち主だけができること

ここからは、本物のチェーンでは、だれにもできないことです。

### 残高を書きかえる

```bash
cast rpc anvil_setBalance $B 0x56BC75E2D63100000
```

```bash
cast balance $B --ether
```

出るはずの結果: `null`、`100.000000000000000000`。

`0x56BC75E2D63100000` は、100 ETH を wei（ETH のいちばん小さい単位）で書いた 16 進数です。取引を送っていないのに、残高が変わります。ブロック番号も増えません（`cast block-number` は `1` のままです）。

### 世界を巻き戻す

```bash
cast rpc evm_snapshot
```

```bash
cast send --unlocked --from $A $B --value 5ether
```

```bash
cast balance $B --ether
```

```bash
cast rpc evm_revert 0x0
```

```bash
cast balance $B --ether
```

```bash
cast block-number
```

出るはずの結果: `"0x0"`（これが印の番号）、送金のあと `105.000000000000000000`、`true`、巻き戻したあと `100.000000000000000000`、ブロック番号は `1`。

- 送金もブロックも、なかったことになります。たたきそこねた鉄を、たたく前に戻せるようなものです。
- 1 つの印は 1 回しか使えません。もう一度戻したいときは、また `evm_snapshot` を打ちます。
- 「同じ出発点から、条件を変えて何度も試す」ときに、この操作を使います。

### 取引がなくてもブロックを掘る

```bash
cast rpc evm_mine
```

```bash
cast block-number
```

出るはずの結果: `"0x0"`、`2`。

### 時計を進める

```bash
cast rpc evm_increaseTime 86400
```

```bash
cast rpc evm_mine
```

```bash
cast block latest -f timestamp
```

```bash
date +%s
```

出るはずの結果: `86400`、`"0x0"`。ブロックの時刻が、いまの時刻より 86,400 秒（1 日）先になります。確かめたときは、ブロックの時刻が `1795574355`、いまの時刻が `1795487955` で、差はちょうど 86,400 でした。ブロック番号は `3` です。

金利や Funding のように「時間がたつと積もるもの」を試すとき、運営する側はこうして時間を進められます。

## 第 1 話で分かったこと

チェーンは、状態を持ち、取引を受け、ブロックを作る、1 つのプログラムです。それを自分で動かすと、残高、時刻、ブロックを作るタイミングを、すべて自分で決められます。

本物のチェーンでこれができないのは、同じプログラムを多くの人が動かしていて、決まりに合わないブロックをほかのノードが受け入れないからです。ここでは、金床が自分の 1 台だけなので、止める人がいません。

| したこと | 使った命令 | 本物のチェーンでは |
|---|---|---|
| 送金する | `cast send` | できる |
| 残高を書きかえる | `anvil_setBalance` | できない |
| 巻き戻す | `evm_snapshot`、`evm_revert` | できない |
| 好きなときにブロックを掘る | `evm_mine` | できない |
| 時計を進める | `evm_increaseTime` | できない |

金床は据わりました。次は、その上にのせるものを作ります。[第 2 話](02_deploy.md) に進みます。anvil は止めずに、そのまま進めてください。
